# 📘 CLAUDE CODE SPECIFICATION v2: Grounded Legal Engine (Singapore Law)

### 1. Grounding Mandate
Every legal assertion, default value, or warning flag generated by the tool must be strictly traceable to an explicit anchor:
1. An extracted clause in the contract,
2. A specific provision of Singapore law (only where §3 below determines it applies), or
3. A documented market benchmark (e.g., an internal playbook version).

The LLM is strictly prohibited from generating un-anchored legal assertions. Fabricated citations, or citations to a provision whose applicability conditions were not checked, are treated as fatal system defects — a correct-sounding citation attached to an inapplicable statute is scored the same as a fabricated one.

**Default posture:** the system's baseline output is document-grounded extraction only (clause → page/paragraph citation). Statutory grounding is the exception path, invoked only where §2 and §3 confirm it is warranted — not applied uniformly across every contract or field.

---

### 2. Contract Classification Gate (NEW — runs before Role A)

Before any statutory default or trigger logic executes, classify each ingested document into one of a fixed set of contract types (e.g. `sale_of_goods`, `services`, `lease`, `nda`, `distribution`, `employment`, `other_unclassified`).

* Classification is itself an extracted, citable fact ("Clause 1.1 identifies this as a distribution agreement") with its own confidence tier (§5) — not an assumption.
* Each statutory module in Role A and Role B declares which contract types it is eligible to fire on (`applicable_contract_types`). A module never runs against a document outside its declared scope.
* Documents classified as `other_unclassified` or with classification confidence below threshold get **no** statutory overlay at all — extraction proceeds, statutory modules are skipped, and the gap is noted in the handoff brief rather than guessed at.

This directly fixes the SOGA-on-an-NDA failure mode: Sale of Goods Act / Supply of Goods Act defaults are only candidates for `sale_of_goods` / `services` classified documents.

---

### 3. Knowledge Library Architecture

Do not feed full raw statutory HTML, PDF, or whole act text files into the model context window. Initialize a structured JSON/vector knowledge store populated strictly with provision-level legal chunks, each carrying explicit applicability conditions and a verification stamp.

```json
{
  "id": "sg_ucta_s2_2",
  "category": "statute",
  "source": "Unfair Contract Terms Act (Cap 396)",
  "provision": "Section 2(2)",
  "exact_wording": "In the case of other loss or damage, a person cannot so exclude or restrict his liability for negligence except in so far as the term or notice satisfies the requirement of reasonableness.",
  "summary": "Liability for negligence (other than death or injury) can only be excluded if reasonable.",
  "role_type": "role_b_validator",
  "applicable_contract_types": ["services", "sale_of_goods", "distribution", "other_commercial"],
  "applicability_conditions": [
    "clause purports to exclude/restrict liability for negligence",
    "AND (party dealt on the other's written standard terms OR one party is a consumer)"
  ],
  "target_fields": ["liability_cap", "uncapped_liability"],
  "trigger_keywords": ["negligence", "exclude", "restrict", "liability"],
  "authority_basis": "statute_text",
  "verified_as_at": "2026-08-15",
  "verified_by": "manual_legal_review"
}
```

Key additions vs. v1:
- `applicable_contract_types` — enforced by the classification gate in §2.
- `applicability_conditions` — the specific factual predicate that must be independently checked (not inferred from field-presence alone) before the chunk can fire. This is what fixes the "UCTA fires on every populated liability field" problem: the predicate itself is now data, not implicit in the trigger.
- `authority_basis` — `statute_text` if the citation rests on the bare provision, or `case_law_gloss` if the application depends on judicial interpretation of the provision (see the Misrepresentation Act note in §4). A chunk whose real authority is a case must cite the case, not just the section.
- `verified_as_at` / `verified_by` — every chunk is treated as hand-curated and lawyer-reviewed content with a version stamp, not live-scraped law. See §7 for how this store gets built.

### 4. Pipeline Roles & Statutory Logic

#### Role A: Default Value Providers (Pre-Extraction, contract-type gated)
Role A injects statutory baseline defaults *before* extraction runs, but only for documents that passed the §2 classification gate into a matching type. If an express clause is extracted during contract analysis, the default is overwritten and the citation status changes from `default_applied` to `overwritten_by_clause`.

* **Sale of Goods Act (Cap 393):** `applicable_contract_types: [sale_of_goods]` only. Pre-populates default fields for title, description, satisfactory quality, fitness for purpose.
* **Supply of Goods Act (Cap 394):** `applicable_contract_types: [services, hire_purchase]` only. Equivalent defaults where SOGA does not apply.
* **Contracts (Rights of Third Parties) Act (Cap 53B):** `applicable_contract_types: [all commercial types]`. Does **not** assume most agreements exclude CRTPA. Instead checks the document for an actual express-exclusion clause; if none is found, flags "no CRTPA exclusion clause detected — third parties may have enforceable rights under this agreement" as a document-grounded absence-finding, not a market-practice assumption.

#### Role B: Post-Extraction Validators (Rules Engine, condition-gated)
Role B operates as a second pass *after* extraction completes, and only evaluates modules whose `applicable_contract_types` match the document's classification **and** whose `applicability_conditions` are independently satisfied by extracted facts — not merely by a field being non-empty.

* **Triggers, Not Conclusions:** Role B surfaces factual triggers and reasonableness-review warnings. It must never render a definitive legal conclusion (e.g. stating a clause is "void" or "unenforceable").
* **Unfair Contract Terms Act (Cap 396):** Fires only where (a) a liability cap/exclusion field is populated, **and** (b) the applicability predicate is checked — is this a negligence-liability exclusion, and is there a standard-terms or consumer-facing element? A freely negotiated B2B cap outside UCTA's reach does not get an s.2(2) citation.
* **Misrepresentation Act (Cap 390):** Fires on "entire agreement" / "non-reliance" clauses, evaluating the s.3 reasonableness import. Citation carries `authority_basis: case_law_gloss` — the knowledge-store chunk must cite the leading case establishing that s.3 catches non-reliance clauses, not just the bare section text.
* **Frustrated Contracts Act (Cap 115):** Low-frequency trigger, fires only where no Force Majeure clause is found at all, flagging the statutory default loss-allocation position as background information — not a prediction of outcome.

### 5. Confidence Tier (NEW)

Every field in the output schema carries an explicit tier, independent of and in addition to the citation:

| Tier | Meaning | Example |
|---|---|---|
| `A_found` | Directly stated in the contract text | "Term: 24 months" — Clause 3.1 |
| `B_inferred` | Statutory default applied because the document is silent, contingent on contract classification being correct | "Satisfactory quality implied" — SOGA s.14(2), contract classified as sale_of_goods |
| `C_flagged` | Post-extraction warning requiring human legal judgment; not a conclusion | "Reasonableness review required" — UCTA s.2(2) |
| `D_unresolved` | Classification failed, applicability conditions not met, or no anchor found at all | "Cannot determine — contract type unclassified" |

`D_unresolved` fields are the ones that must route into the escalation handoff brief (§6), not be silently omitted or filled with a best guess.

---

### 6. Escalation / Handoff Brief Integration (NEW)

Role B flags and `D_unresolved` fields are not just stored per-field — they are the primary input to the handoff brief:

```json
{
  "handoff_item": {
    "issue": "Liability cap clause may require reasonableness review",
    "documents": ["Distribution Agreement — Acme Pte Ltd, Clause 12.1"],
    "established": "Clause 12.1 caps liability at S$50,000; contract was signed on Acme's standard terms",
    "basis": "Unfair Contract Terms Act (Cap 396), s.2(2); reasonableness test applies as this appears to be standard-terms dealing",
    "open_question": "Is the S$50,000 cap reasonable given the contract value and risk allocation? Requires lawyer assessment of s.11 UCTA factors.",
    "confidence_tier": "C_flagged"
  }
}
```

This satisfies the brief's requirement that the tool "decide when a lawyer is needed and make that lawyer's first hour cheap" — every `C_flagged` and `D_unresolved` item should be renderable directly as one of these entries with no further authoring.

---

### 7. Shared Validation Logic (Reasonableness Gate)
Implement a unified function `reasonableness_gate(clause_text, context, applicability_conditions)` shared by UCTA and Misrepresentation Act triggers, since s.3 of the Misrepresentation Act imports the UCTA s.11 reasonableness test under Singapore law. The function now takes `applicability_conditions` as an explicit argument and returns a no-fire result if the predicate (standard terms / consumer dealing / negligence-specific exclusion) isn't independently satisfied — it does not fire on field-presence alone.
