# 📘 CLAUDE CODE SPECIFICATION: Grounded Legal Engine (Singapore Law)

### 1. Grounding Mandate
Every legal assertion, default value, or warning flag generated by the tool must be strictly traceable to an explicit anchor:
1. An extracted clause in the contract,
2. A specific provision of Singapore law, or
3. A documented market benchmark (e.g., an internal playbook version).

The LLM is strictly prohibited from generating un-anchored legal assertions. Fabricated citations or unsupported statements are treated as fatal system defects.

---

### 2. Knowledge Library Architecture
Do not feed full raw statutory HTML, PDF, or whole act text files into the model context window. Initialize a structured JSON/Vector knowledge store populated strictly with provision-level legal chunks.

```json
{
  "id": "sg_ucta_s2_2",
  "category": "statute",
```

### 3. Pipeline Roles & Statutory Logic

#### Role A: Default Value Providers (Pre-Extraction)
Role A injects statutory baseline defaults *before* extraction runs. If an express clause is extracted during contract analysis, the default is overwritten.
* **Sale of Goods Act (Cap 393):** Pre-populates default fields for title, description, satisfactory quality, and fitness for purpose.
* **Supply of Goods Act (Cap 394):** Applies equivalent defaults for services and hire-purchase contracts where SOGA does not apply.
* **Contracts (Rights of Third Parties) Act (Cap 53B):** Pre-populates the default assumption that third parties may enforce rights, flagged for a high-priority overwrite (as most commercial agreements expressly exclude CRTPA).

#### Role B: Post-Extraction Validators (Rules Engine)
Role B operates as a second pass *after* extraction completes. It reads already-populated fields and appends warning flags without altering the original extracted text.
* **Triggers, Not Conclusions:** Role B surfaces factual triggers and reasonableness review warnings. It must never render a definitive legal conclusion (e.g., stating a clause is "void").
* **Unfair Contract Terms Act (Cap 396):** Triggers when a liability cap or exclusion-type field is populated.
* **Misrepresentation Act (Cap 390):** Triggers conditionally on fields containing "entire agreement" or "non-reliance" clauses (evaluating s.3 reasonableness requirements).
* **Frustrated Contracts Act (Cap 115):** Low-frequency trigger firing only when a contract lacks a Force Majeure clause entirely, flagging statutory default loss-allocation rules (loss lies where it falls, minus recoverable prepayments/expenses).

---

### 4. Shared Validation Logic (Reasonableness Gate)
Implement a unified function `reasonableness_gate(clause_text, context)` shared by UCTA and Misrepresentation Act triggers, as s.3 of the Misrepresentation Act imports the UCTA s.11 reasonableness test under Singapore law.

---

### 5. Grounded JSON Schema Output
To guarantee complete auditability, all pipeline outputs must include mandatory citation fields.

#### Role A Schema Output Example:
```json
{
  "satisfactory_quality": {
    "value": "Goods must be of satisfactory quality.",
    "status": "default_applied",
    "citation": "Sale of Goods Act (Cap 393), Section 14(2)",
    "overwritten_by_clause": null
  }
}
```
